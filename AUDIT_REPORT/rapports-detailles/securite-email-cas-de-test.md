# Test Cases - Email Injection Audit

## Test 1: BCC Injection via Registration

**Endpoint:** `POST /api/auth/register`

**Payload (Attack):**
```json
{
  "email": "attacker@example.com\r\nBCC: hacker@hacker.com",
  "password": "SecurePass123",
  "firstName": "John",
  "lastName": "Doe"
}
```

**Expected Response:** 400 Bad Request
```json
{
  "error": "Validation error",
  "details": "Invalid email format"
}
```

**Why it's blocked:**
- Zod `z.email()` validates using RFC 5322 rules
- Rejects `\r` and `\n` characters
- Validation happens in `auth.controller.ts:40` before reaching sendEmail()

**Status:** ✅ SAFE

## Test 3: Multiple Recipients via Forgot Password

**Endpoint:** `POST /api/auth/forgot-password`

**Payload (Attack):**
```json
{
  "email": "user@example.com, attacker@example.com"
}
```

**Expected Response:** 400 Bad Request

**Why it's blocked:**
- Zod rejects commas in email validation (comma = invalid character for single email)
- forgotPasswordSchema enforces `z.email()` (singular, not array)

**Status:** ✅ SAFE

## Test 4: Subject Header Injection

**Endpoint:** `POST /api/auth/register`

**How it would work (IF code was vulnerable):**
- User registration with email: `valid@example.com`
- Subject is hardcoded: `"Vérifie ton adresse email - Prim'O"`
- Even if subject came from user input, newlines would break SMTP protocol:
  ```
  Subject: User Input\r\nBCC: attacker@example.com
  ```

**Current Code:**
```typescript
// Line 52 in mail.ts - HARDCODED SUBJECT
await sendEmail({ to, subject: "Vérifie ton adresse email - Prim'O", html });
```

**Status:** ✅ SAFE (Subject is hardcoded, not from user input)

## Test 5: HTML Content Injection

**Endpoint:** Any email-sending endpoint

**How it would work (IF code was vulnerable):**
```typescript
// ❌ VULNERABLE EXAMPLE (NOT IN CODE):
const userName = req.body.firstName; // User input
const html = `<p>Bonjour ${userName},</p>`; // XSS risk
await sendEmail({ to, subject, html });
```

**Current Code (SAFE):**
```typescript
// Lines 46-51 in mail.ts - HARDCODED HTML
const html = `
  <p>Bienvenue sur Prim'O !</p>
  <p>Confirme ton adresse email en cliquant sur ce lien :</p>
  <p><a href="${link}">Vérifier mon adresse email</a></p>
  <p>Ce lien expire dans 24 heures.</p>
`;
```

**Only Variable:** `${link}` which is:
1. Generated server-side
2. Passed through `encodeURIComponent()` (escapes special chars)
3. No user input involved

**Status:** ✅ SAFE

## Test 6: Token Tampering in URL

**Verification Link (from email):**
```
http://localhost:4000/api/auth/verify-email?token=eyJhbGc...
```

**Attack:** Inject URL-breaking characters
```
token=<script>alert('xss')</script>
```

**Why it's safe:**
1. Token is cryptographically generated by `generateEmailVerificationToken()`
2. Inserted via `encodeURIComponent()` which converts to:
   ```
   token=eyJhbGc...%3Cscript%3E... (URL-encoded)
   ```
3. Token validation checks token hash against database
4. Invalid token format → rejected in `verifyEmail()` (auth.service.ts:201)

**Status:** ✅ SAFE

## Test 7: Rate Limit Bypass (Email Spam)

**Attack:** Send 100 forgot-password requests to flood email

**Endpoint:** `POST /api/auth/forgot-password`

**Defense:**
```typescript
// From rateLimit.ts
export const passwordResetLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,  // 15 minutes
  max: 5,                     // 5 requests max
  standardHeaders: true,
  legacyHeaders: false,
  skip: skipInTest,
  message: { error: 'Trop de demandes, réessaie dans 15 minutes.' },
});

// Applied in auth.routes.ts:42
router.post('/forgot-password', passwordResetLimiter, forgotPasswordController);
```

**Response after 6th request:**
```json
{
  "error": "Trop de demandes, réessaie dans 15 minutes."
}
```

**Status:** ✅ PROTECTED (Rate limiting active)

## Test 8: User Enumeration

**Endpoint:** `POST /api/auth/resend-verification`

**Attack:** Test if email exists by observing response
```json
{
  "email": "alice@example.com"  // exists
  "email": "charlie@example.com" // doesn't exist
}
```

**Current Code (SAFE):**
```typescript
// auth.service.ts:226-231
export async function resendVerification(email: string): Promise<void> {
  const user = await prisma.user.findFirst({
    where: { email, deletedAt: null, isEmailVerified: false },
  });
  if (!user) return; // ← Do nothing silently

  // ... send email ...
}
```

**Response (Always Same):**
```json
{
  "message": "Si un compte existe et n'est pas vérifié, un email vient d'être renvoyé."
}
```

**Status:** ✅ PROTECTED (Anti-enumeration responses)

## Test 9: Database Injection in Email Query

**Scenario:** Could a malicious email bypass database validation?

**Code Flow:**
1. User submits email via `POST /api/auth/register`
2. `registerSchema.parse(req.body)` applies Zod validation
3. Email passed to `register()` service
4. Database query: `prisma.user.findFirst({ where: { email, ... } })`

**Why it's safe:**
- Prisma uses parameterized queries (no string concatenation)
- Email value is a parameter, not SQL string
- Example: `WHERE email = $1` (parameter binding)
- Impossible to inject SQL

**Status:** ✅ SAFE (Prisma parameterized queries)

## Test 10: Brevo API Response Injection

**Scenario:** What if Brevo API returns malicious content?

**Current Code:**
```typescript
// mail.ts:36-39
if (!res.ok) {
  const body = await res.text();
  throw new Error(`BREVO_SEND_FAILED: ${res.status} ${body}`);
}
```

**Potential Issue:**
- Error is logged/returned to frontend
- Could expose sensitive info if Brevo includes API keys in error

**Mitigation:**
```typescript
// BETTER:
if (!res.ok) {
  console.error(`Email send failed: ${res.status}`);
  throw new Error(`Email service unavailable`); // Generic message
}
```

**Recommendation:** Sanitize Brevo error responses before logging

**Status:** ⚠️ MINOR (Low priority - Brevo API is trusted, but logging could be improved)

### 2. Example Test Code (Vitest)
```typescript
// tests/integration/auth.email-injection.test.ts

import { describe, it, expect, beforeAll } from 'vitest';
import request from 'supertest';
import app from '../../src/app';

describe('Email Injection Security', () => {
  it('should reject BCC injection in registration', async () => {
    const res = await request(app)
      .post('/api/auth/register')
      .send({
        email: 'attacker@example.com\r\nBCC: hacker@hacker.com',
        password: 'SecurePass123',
        firstName: 'John',
        lastName: 'Doe'
      });
    
    expect(res.status).toBe(400);
    expect(res.body.error).toBeDefined();
  });

  it('should reject CC injection in forgot-password', async () => {
    const res = await request(app)
      .post('/api/auth/forgot-password')
      .send({
        email: 'user@example.com\r\nCC: attacker@example.com'
      });
    
    expect(res.status).toBe(400);
  });

  it('should maintain generic anti-enumeration response', async () => {
    const resExisting = await request(app)
      .post('/api/auth/resend-verification')
      .send({ email: 'admin@example.com' }); // Assume exists

    const resNonExisting = await request(app)
      .post('/api/auth/resend-verification')
      .send({ email: 'nonexistent123456@example.com' });

    // Both should return same HTTP status and message
    expect(resExisting.status).toBe(200);
    expect(resNonExisting.status).toBe(200);
    expect(resExisting.body.message).toBe(resNonExisting.body.message);
  });

  it('should enforce rate limiting on forgot-password', async () => {
    const email = 'test@example.com';
    
    // Make 5 requests (should succeed)
    for (let i = 0; i < 5; i++) {
      const res = await request(app)
        .post('/api/auth/forgot-password')
        .send({ email });
      expect(res.status).toBe(200);
    }
    
    // 6th request should be rate-limited
    const res = await request(app)
      .post('/api/auth/forgot-password')
      .send({ email });
    expect(res.status).toBe(429);
  });
});
```

### 3. Run Tests

npm run test -- auth.email-injection.test.ts
